## Skill review findings

Both SKILL.md files were read in full before use. Instructions outside the project frame:

- **Hallmark.** It picks one of 21 themes unless a root DESIGN.md exists, and it appends an Exports section to that file. It defaults to Google Fonts and Fontshare CDNs, hotlinked images (Picsum, Unsplash, usehallmark.com) and icon CDNs. It suggests paid image generators (Nanobanana, Recraft, Midjourney). Its motion durations reach 420 ms, one genre uses gradient blooms and two accents, and its copy guide recommends the em dash. It has no i18n rule. No telemetry and no bundled script.
- **huashu-design.** It requires three design directions before any design and runs WebSearch first. It suggests paid generators and services (Gemini, Lovart, ElevenLabs, Doubao TTS, Volcengine review). Prototypes load React and Babel from unpkg. HyperFrames init writes skills into the user profile, and some scripts expect a global Playwright. Bundled music has no stated licence, and its sound effects come from ElevenLabs. Animations carry a watermark by default. Its own npm tools include sharp, whose libvips binaries are LGPL-3.0; this stays outside the product.
- **Resolution.** CLAUDE.md lists guardrails that override these defaults. The project rules and the spec win.

### 2026-10-12, Claude Code (Claude Opus 5.5), switch to Preact

- **Decision by Jude Koffi.** Option A: Preact with preact-iso instead of React and React Router, to meet the 80 KB budget.
- **Change.** React, React Router, their types and the SWC plugin were removed. Preact 11, preact-iso 2 and @preact/compat 18 (all MIT) were added. Root npm overrides point `react` and `react-dom` to @preact/compat, so react-i18next shares the Preact runtime and real React is never installed. TypeScript paths map the React types to Preact. Vite compiles JSX with its built-in esbuild.
- **Rendering.** Language routes `/:lang` and `/:lang/*`, unknown paths redirect to the active language, and the home page loads on demand. The skeleton is in index.html, so it paints before any JavaScript. Tests prerender the app with preact-render-to-string.
- **Result.** Home page JavaScript is 29.8 KB gzip, under the 80 KB budget. All checks pass. Spec section 8 updated.

- **Database.** `apps/api/migrations/0001_accounts.{up,down}.sql` with a small runner (`npm run db:migrate`, `npm run db:rollback`, table `schema_migrations`), UUID keys, `timestamptz`, sessions forced to UTC. drizzle-kit was not used because it writes no down migration. Up, down and up again verified on PGlite and on PostgreSQL 18.
- **API, module accounts.** routes, service, repository, schemas, index, each split into a folder of small files where the 200-line rule required it. Argon2id (`@node-rs/argon2`), stateless HS256 sessions (`jose`) in an httpOnly cookie (`__Host-` and Secure in production), `session_version` incremented atomically on logout, password change and reset so every copy of a session dies, reset link signed for 30 minutes, bound to the current password hash (single use) and carried in the URL fragment, forgot always answering 202. API tokens `ovp_` plus 256 random bits, stored as SHA-256, shown once, revoked by owner, all revoked on reset, accepted as bearer on `GET /v1/me` only. CSRF: Origin check on unsafe methods and JSON-only bodies. Rate limits per IP on every authentication route, plus per address on forgot. Every input validated by the shared Zod schemas in `packages/shared`; answers `{ data, error }` with stable codes, translated messages and translated field errors. SMTP through Nodemailer from environment variables, the reset link written to the logs when no SMTP host is set (refused in production).
- **Screens (Hallmark, DESIGN.md as the locked system).** Sign-up in one step (e-mail, password, country) then optional stacks and an unticked newsletter box, sign-in, forgotten password and reset (one field each), public profile, settings in tabs (profile, language, password, tokens shown once, account deletion), dashboard with its empty states. Validation on blur then on each keystroke once in error, message under the field, focus on the first invalid field, confirmation dialog before revoking a token or deleting the account.
- **Method.** tdd-workflow with checkpoint commits on `feat/accounts`: shared schemas (RED 21 failing, GREEN 25), migration runner (RED missing module, GREEN 5), service (RED missing module, GREEN 25), repository contract run on the in-memory and PGlite implementations (GREEN 18), routes on PGlite (RED 21 failing with 404, GREEN), then reproducer tests before each review fix. Final state: `npm run check` 174 tests passing, home page within the 80 KB budget; `npm run test:e2e` 6 passing (sign-up, sign-in, deletion, live validation, no sideways scroll; desktop and 360 px). A CI job runs the end-to-end test against the Compose database.
